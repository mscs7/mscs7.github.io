What I am building

One evidence model. Different assessment modes.

A workflow tool rather than a claim that one scan can replace a penetration test. Inventory, observations and unverified candidates remain separate.

01 / WEB

Discover and inspect

Public technology fingerprints, version hints, login-form discovery, selected paths and API-document inventory. Opt-in parameter diagnostics compare baseline, control and mutation responses.

HTTP / OpenAPI / Input handling
02 / NETWORK

Map approved services

Native TCP checks on one approved IP. An optional Nmap adapter imports service/version evidence. Gobuster, DIRB and ffuf adapters support controlled content discovery.

TCP / Nmap XML / Scanner adapters
03 / ACTIVE DIRECTORY

Review directory posture

Analyze a read-only export for selected account flags, password-policy settings and delegation configuration. A separate PowerShell collector requires Windows lab validation.

PowerShell / JSON / Offline analysis
Engineering decisions

Conclusions should follow evidence.

The useful part is not how many commands run. It is whether the output is understandable, reproducible and honest about coverage.

Evidence-linked observations

Native request timestamps, response-sample hashes and evidence IDs are retained without storing raw response bodies.

Candidate is not confirmed

SQL/NoSQL error signals, advertised versions and Metasploit metadata matches require human validation.

Incomplete is not passed

Missing binaries, failed requests, record caps and skipped modules remain visible in coverage.

Reproducible local fixture

Positive and negative synthetic cases demonstrate the workflow without targeting a public system.

Validation and boundaries

What this release proves.

Tested in the build environment

100 regression cases passed. Native loopback HTTP discovery, diagnostic comparisons, a local TCP connection and synthetic AD-export analysis ran successfully. The three-page DOCX report was rendered and checked. The package wheel was built.

What still requires lab validation

Nmap, Gobuster, DIRB and ffuf actual-binary runs; the PowerShell collector against a Windows domain; the full real Metasploit metadata catalogue; and live NVD API responses. Adapter commands/parsers were tested with fixtures, not those live integrations.

What this is not

Not a complete API scanner, a Wappalyzer replacement, an autonomous AI agent or all-in-one AD exploitation. It does not perform credential attacks, exploit execution or lateral movement. An inconclusive injection diagnostic is not a clean bill of health.

Project lead: Mohammed Suhail C S. Initial implementation developed with AI assistance. Upstream scanners retain their own authorship and licenses. Public examples contain synthetic data only.
