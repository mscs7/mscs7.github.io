SUHAIL.CS - V4 PUBLIC CASE-STUDY UPGRADE
=========================================

This is a SAFE, ADDITIVE patch for your existing GitHub Pages portfolio:
https://github.com/mscs7/mscs7.github.io

What you get
------------
- 13 unique interactive case-study demonstrations embedded below the workflow section.
- A rack + router + ISP path, blinking status LEDs and simulated Proxmox terminal.
- VLAN selection and animated network flow; Cloudflare/DNS/AWS/CloudWatch concepts.
- Local CRM/attendance/exam workflow demos; hardware mock screens; MFA policy UI;
  synthetic SIEM alerts; CVE lab board; VAPT and incident timeline; tool demo panels.
- Next / Previous / All work links at the end of each case page plus desktop Next link.
- No real network calls, credentials, shell commands or live scanners.

How to publish through github.com (no terminal required)
---------------------------------------------------------
1. BACK UP your GitHub repository first: Code > Download ZIP.
2. Extract this V4 zip on your Windows computer.
3. Visit https://github.com/mscs7/mscs7.github.io and select the Pages branch.
4. Choose Add file > Upload files.
5. DRAG THE CONTENTS OF THIS FOLDER, NOT THE ENCLOSING FOLDER.
   The root must contain v4-dashboard.js and v4-dashboard.css.
   The work/ folder must merge into your existing work/ folder.
6. Commit. The 13 files at work/<project>/index.html replace their old versions.
7. Wait for the GitHub Pages Actions deployment to show success.
8. Open https://mscs7.github.io/work/hosting-infrastructure/ and refresh.
   Scroll to INTERACTIVE FIELD GUIDE. Try qm list in the terminal.
   Then use the Previous / Next work navigation near the bottom.

Files deliberately NOT included
-------------------------------
content.js, work-content.js, existing homepage, styles.css, case-study.js,
existing WP Scope/ScopeForge showcase pages, CV PDFs, portrait and other assets.
No browser editors are included. Do not publish tools/work-editor.* or tools/editor.*.
If those files already exist publicly, delete them from the GitHub repository;
uploading this patch does NOT automatically remove them.

Personalisation
---------------
- Wording of work case studies: your PRIVATE LOCAL work editor -> exported
  content.js, or edit your existing work-content.js content carefully.
- Interactive demo visuals, sample records and mock terminal responses:
  edit v4-dashboard.js using VS Code locally; publish the edited JS file only.
- Colours/animation/responsive CSS: edit v4-dashboard.css.
- Homepage contacts/location: leave site-config.js as already configured.
- Keep project IDs and /work/<slug>/ paths stable for previously shared links.

Information and security
------------------------
All interface output is illustrative and generated by your visitor's browser.
The Proxmox terminal is a whitelist of demo text, never a real terminal.
The networking panel has fake VLAN names and no actual network access.
The device panels do not transmit RF, perform Wi-Fi scans, or emulate USB payloads.
The tool report examples have no real findings or live scanner execution.
No scripts send form data or private information to external servers.
Do not put confidential client topologies, IPs, incident artifacts or secrets here.

Rollback
--------
Use your backup or GitHub's commit history to revert these changes.
For V4 alone, removing the new CSS/JS script references and both v4-dashboard
files restores the older case-study experience.
