ENGINEERING FOCUS

More than a sequence of commands.

The project focuses on the parts that make automated assessments understandable: explicit boundaries, useful evidence and honest conclusions.

01 / SCOPE

Know what is authorized.

Exact native origin and path checks, pinned DNS, request budgets and blocked off-scope redirects. Network scanning needs a separately approved IP.

02 / EVIDENCE

Separate facts from findings.

Public routes are inventory. Header gaps are hardening observations. External advisory matches remain candidates until an analyst validates them.

03 / DELIVERY

Make the output useful.

Readable reports include scope, evidence IDs, confidence, remediation, module coverage and limitations instead of an unexplained scanner dump.

HOW IT WORKS

A repeatable assessment path.

  1. Validate the approved target and record the engagement.
  2. Identify WordPress indicators and inventory public components.
  3. Run bounded native checks; optionally invoke installed scanner adapters.
  4. Export evidence and review observations before final reporting.
HONEST RELEASE STATUS

Prototype, not an autopilot pentest.

Implemented: native checks, report exports, local demonstration and automated regression tests.

Optional integrations: WPScan, WPProbe, ffuf and Nmap. Command builders and parser fixtures are tested; real-tool compatibility still needs lab validation.

Not included: exploitation, password attacks, full authenticated API testing or autonomous AI decisions.
